## 먼저 잡고 갈 관점

프론트엔드에서는 **한 사용자의 한 화면**이 세계의 전부다. 상태는 브라우저 탭 하나에 갇혀 있고
내가 망쳐도 새로고침하면 사라진다.

백엔드는 정반대다.

1. **동시에 수천 개가 돈다.** 내가 짠 함수는 지금 이 순간 500번 병렬로 실행 중이다. 전역 변수에 값을 담는 순간 버그다.
   React 컴포넌트 바깥에 `let count = 0` 을 두면 모든 컴포넌트 인스턴스가 그 값을 나눠 쓰는 것과 같은데, 서버에서는 그 "인스턴스"가 서로 다른 사용자들이다.
2. **상태가 영구히 남는다.** 잘못 쓴 데이터는 새로고침으로 안 사라진다. 그래서 트랜잭션과 검증이 있다.
   트랜잭션은 여러 개의 쓰기를 "전부 성공 아니면 전부 취소"로 묶는 DB 기능이다(`03-database.md`).
3. **신뢰 경계가 여기다.** 신뢰 경계는 "여기부터는 들어오는 값을 믿지 않고 다시 검사한다"는 선이다.
   프론트에서 한 모든 검증은 UX 일 뿐이다. 사용자는 DevTools 나 curl 로 프론트를 거치지 않고 요청을 보낼 수 있으므로 진짜 차단은 서버에서만 일어난다.
4. **호출자를 모른다.** 내 API 를 부르는 게 우리 프론트인지, 고객사 배치 스크립트인지, 재시도 중인 큐인지 모른다.
   같은 요청이 두 번 올 수도 있고 순서가 뒤바뀌어 올 수도 있다.

이 네 가지가 백엔드 코드가 프론트 코드보다 방어적이고 계층이 많은 이유의 전부다.
앞으로 나올 장치는 모두 이 넷 중 하나에 대한 대응이다.
