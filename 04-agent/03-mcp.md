# MCP (Model Context Protocol)

**이미 쓰고 있는 것이다.** Claude Code 에 MCP 서버를 붙여 팀 컨텍스트 레포를 연결한 경험이 있다.
여기서는 그게 프로토콜로서 무엇이고, 제품에서 왜 중요한지를 정리한다.

---

## 1. 왜 표준이 필요했나

도구가 M개, 모델·클라이언트가 N개면 연동이 **M × N** 개 필요했다.

```
Claude Code ─┬─ GitHub 연동 (직접 구현)
             ├─ Slack 연동 (직접 구현)
Cursor      ─┼─ GitHub 연동 (또 구현)
             └─ Slack 연동 (또 구현)
```

MCP 는 그 사이에 표준 계층을 넣어 **M + N** 으로 바꾼다.

```
[클라이언트: Claude Code / Cursor / 우리 제품]
        │  MCP (JSON-RPC 2.0)
[서버: GitHub / Slack / 사내 DB / 고객사 시스템]
```

USB-C 비유가 흔히 쓰인다. **어댑터 표준.**

---

## 2. 구성 요소

| 개념 | 설명 | 주도권 |
| --- | --- | --- |
| **Tools** | 모델이 호출하는 함수 | **모델이 결정** |
| **Resources** | 읽을 수 있는 데이터 (파일, DB 행, API 응답) | 애플리케이션이 결정 |
| **Prompts** | 재사용 가능한 프롬프트 템플릿 | 사용자가 선택 |
| **Sampling** | 서버가 클라이언트에게 LLM 호출을 요청 | 서버가 요청 |
| **Roots** | 서버가 접근 가능한 경로 범위 | 클라이언트가 제한 |

**Tools 와 Resources 의 차이가 헷갈리는데, 누가 결정하느냐가 다르다.**
Tool 은 모델이 "이걸 부르겠다"고 판단하고, Resource 는 앱이 "이걸 컨텍스트에 넣겠다"고 결정한다.

### 전송 방식

- **stdio** — 로컬 프로세스. Claude Code 에서 쓰던 그것
- **Streamable HTTP** — 원격 서버. 엔터프라이즈 배포는 이쪽

---

## 3. 랭코드 맥락에서 왜 중요한가

대표 인터뷰의 핵심이 **"비표준 시스템 연동"** 과 **"벤더 락인 회피"** 였다.

| 회사가 말한 것 | MCP 로 보면 |
| --- | --- |
| 여러 AI 를 통합 관리하는 허브 | 클라이언트 쪽 표준화 |
| 고객사 시스템 연동 | 고객사마다 MCP 서버를 하나씩 만든다 |
| 벤더 중립 | 모델을 바꿔도 도구 계층은 그대로 |

**"고객사 A 의 레거시 시스템을 MCP 서버로 감싼다"** 가 실제 업무 형태일 수 있다.
그러면 `01-backend-basics/02-layers-and-di.md` 의 어댑터 계층 이야기와 완전히 같은 구조가 된다.

> ❓ 입사 후 확인: 고객사 연동을 MCP 로 하나, 자체 어댑터 인터페이스로 하나, 둘 다인가?

## 4. 보안 — 반드시 아는 것

MCP 서버를 붙이는 건 **에이전트에게 권한을 주는 일**이다.

| 위험 | 설명 |
| --- | --- |
| **도구 설명 인젝션** | 서버가 주는 tool description 안에 악의적 지시를 넣을 수 있다. 신뢰할 수 있는 서버만 |
| **과도한 권한** | 읽기만 필요한데 쓰기 도구까지 노출 → 최소 권한 |
| **혼동된 대리인 (confused deputy)** | 에이전트가 사용자보다 높은 권한으로 도구를 실행 → **도구 실행 시 사용자 권한을 전파해야 한다** |
| **데이터 유출** | 도구 결과가 모델 컨텍스트로 들어가고, 그게 다른 도구 호출에 쓰일 수 있다 |
| **부작용** | 삭제·전송·결제는 사람 승인 |

세 번째가 엔터프라이즈에서 특히 중요하다. 에이전트가 서비스 계정으로 동작하면,
**권한 없는 사용자가 에이전트를 통해 모든 문서를 볼 수 있게 된다.**
→ `03-rag/04-enterprise-rag.md` 의 권한 필터링과 같은 문제.

---

## 5. 내 경험을 어떻게 이어붙이나

팀 간 정보 단절을 MCP 로 연결한 공유 컨텍스트 레포를 만들어봤다는 건,
**"에이전트에게 무엇을 보여줄지 설계해본 경험"** 이다.

거기서 겪은 문제들이 제품에서도 똑같이 나온다.
- 무엇을 노출하고 무엇을 감출 것인가 (컨텍스트 예산)
- 도구 설명을 어떻게 써야 모델이 제대로 쓰는가
- 정보가 오래되면 어떻게 되는가 (동기화)

**과장하지 말 것:** MCP 서버를 붙여 쓴 것과 프로토콜 구현·엔터프라이즈 배포는 다르다.
아는 만큼만 말하고, 겪은 문제는 자신 있게 말하면 된다.
