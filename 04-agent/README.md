## 읽는 순서

01 을 먼저 읽는다. 02 와 03 은 01 에 나오는 "도구 호출 루프"를 각각 다른 방향으로 확장한 이야기라 01 없이 읽으면 용어만 남는다.

- 01 은 프레임워크 없이 에이전트가 어떻게 돌아가는지 설명한다. 모델이 JSON 으로 "이 함수를 불러 달라"고 요청하고 우리 코드가 실행해 결과를 돌려주는 반복문이 전부다.
- 02 는 그 반복문을 .NET 에서 대신 돌려주는 프레임워크(MAF)를 다룬다.
- 03 은 도구를 어디서 가져오느냐의 문제다. 도구를 표준 프로토콜(MCP)로 꽂아 쓰면 모델이나 앱을 바꿔도 도구를 다시 만들지 않아도 된다.

## 미리 알아 두면 편한 말

세 문서에 걸쳐 계속 나오는 말이라 여기서 한 줄씩 먼저 적어 둔다.

- 토큰(token): 모델이 글을 읽고 쓰는 단위. 요금과 입력 한도가 전부 토큰 수로 계산된다.
- 컨텍스트 윈도우(context window): 모델이 한 번에 볼 수 있는 토큰의 최대치. 대화 기록, 도구 설명, 도구 결과가 모두 이 안에 들어가야 한다.
- 도구(tool): 모델이 "불러 달라"고 요청할 수 있게 이름과 설명을 붙여 둔 함수. function 이라고도 부른다.
- 오케스트레이션(orchestration): 여러 단계나 여러 에이전트 중 무엇을 언제 실행할지 정하고 결과를 넘겨주는 조율 작업.
